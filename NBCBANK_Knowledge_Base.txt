# [Highest-priority patch] Chart renderer strict-JSON compatibility rule

This patch has higher priority than all later descriptions about charts, visualization, native REPORT charts, statistical summaries, and Top 10 displays.

## 1. General rule
1. Charts must still be generated only by `REPORT_GENERATOR_NODE` based on SQL rows or SQL aggregation results.
2. `PYTHON_GENERATE_NODE` remains prohibited by default unless the user explicitly asks for an exported standalone image, Excel, CSV, HTML file, or complex statistical modeling.
3. If the frontend chart renderer uses ECharts code blocks, the output must be a **strict JSON ECharts option**.
4. `REPORT_GENERATOR_NODE` must not output JavaScript-style ECharts option objects.

## 2. Required ECharts code-block format
Allowed format:
```echarts
{
  "title": {"text": "Top 10 candidates", "left": "center"},
  "tooltip": {"trigger": "axis", "axisPointer": {"type": "shadow"}, "formatter": "{b}<br/>Supporting genes: {c}"},
  "xAxis": {"type": "value", "name": "Supporting genes"},
  "yAxis": {"type": "category", "data": ["A", "B", "C"], "axisLabel": {"interval": 0}},
  "series": [{"name": "Supporting genes", "type": "bar", "data": [3, 5, 8], "label": {"show": true, "position": "right"}}]
}
```

## 3. Forbidden inside any ECharts code block
Never output any of the following inside an `echarts` code block:
1. JavaScript functions, such as `function (value) { ... }`.
2. Arrow functions, such as `() => ...`.
3. Comments, such as `// ...` or `/* ... */`.
4. Raw multiline strings. Prefer `"{b}<br/>Supporting genes: {c}"` instead of a formatter string containing a real line break.
5. `undefined`, `NaN`, `Infinity`, variable references, or Date objects.
6. Trailing commas.
7. Single-quoted keys or strings.
8. Function-based label truncation in `axisLabel.formatter`.

## 4. Long-label handling
1. Do not truncate labels with `formatter: function(value){...}` inside the chart JSON.
2. Prefer keeping full labels and setting `axisLabel.interval = 0`.
3. If shortened labels are necessary, precompute a `display_name` at the report layer and write the shortened strings directly into `yAxis.data` or the dataset. Do not use a chart-side function.
4. Keep full names in the table below the chart.

## 5. Fallback rule
1. If the chart block cannot be guaranteed to be directly parseable by `JSON.parse`, do not output an `echarts` code block.
2. Fall back to a Markdown Top 10 ranking table, distribution table, or evidence-stratification table.
3. Do not switch to Python because ECharts rendering fails.

## 3. Unified dictionary-diagnosis SQL rules
### 3.0 Nature of this section
This section is not final SQL and must not be copied literally. `SQL_GENERATE_NODE` must extract real keywords from the user question and insert them into final SQL.

### 3.1 Exact matching
Exact matching must not preset `type`. It must first read `alias / standard_value / type / etype`.

Template:
```sql
SELECT alias, standard_value, type, etype
FROM dict_synonyms
WHERE alias = 'USER_KEYWORD'
   OR standard_value = 'USER_KEYWORD';
```

English example:
```sql
SELECT alias, standard_value, type, etype
FROM dict_synonyms
WHERE alias = 'resveratrol'
   OR standard_value = 'resveratrol';
```

Gene example:
```sql
SELECT alias, standard_value, type, etype
FROM dict_synonyms
WHERE alias = 'FFAR4'
   OR standard_value = 'FFAR4';
```

### 3.2 Limited fuzzy matching
Limited fuzzy matching is allowed only for:
- `天然植物`
- `功能组分`
- `无靶标成分`
- `一级表观`
- `二级表观`
- `三级表观`
- `四级表观`

It is forbidden for:
- target/gene;
- species;
- annotation / GO / KEGG / pathway IDs.

Template:
```sql
SELECT
    d.alias,
    d.standard_value,
    d.type,
    d.etype,
    CASE
        WHEN d.alias = 'USER_KEYWORD' OR d.standard_value = 'USER_KEYWORD' THEN 100
        WHEN REPLACE(REPLACE(REPLACE(REPLACE(LOWER(d.alias), ' ', ''), '-', ''), '（', ''), '）', '') =
             REPLACE(REPLACE(REPLACE(REPLACE(LOWER('USER_KEYWORD'), ' ', ''), '-', ''), '（', ''), '）', '') THEN 95
        WHEN LOWER(d.alias) LIKE CONCAT(LOWER('USER_KEYWORD'), '%') THEN 85
        WHEN LOWER(d.alias) LIKE CONCAT('%', LOWER('USER_KEYWORD'), '%') THEN 75
        WHEN LOWER('USER_KEYWORD') LIKE CONCAT('%', LOWER(d.alias), '%') THEN 70
        ELSE 0
    END AS match_score
FROM dict_synonyms d
WHERE d.type IN ('天然植物','功能组分','无靶标成分','一级表观','二级表观','三级表观','四级表观')
  AND (
       LOWER(d.alias) = LOWER('USER_KEYWORD')
    OR LOWER(d.standard_value) = LOWER('USER_KEYWORD')
    OR LOWER(d.alias) LIKE CONCAT('%', LOWER('USER_KEYWORD'), '%')
    OR LOWER('USER_KEYWORD') LIKE CONCAT('%', LOWER(d.alias), '%')
  )
ORDER BY match_score DESC, CHAR_LENGTH(d.alias) ASC, CHAR_LENGTH(d.standard_value) ASC
LIMIT 10;
```

### 3.3 Dictionary-result handling
- exact unique hit: enter the business CLASS;
- exact multiple hits: ask for confirmation, do not execute business SQL;
- no exact hit but fuzzy top score is 100 or 95 and unique: enter the business CLASS;
- no exact hit but fuzzy top score ≥85, no tie, and ≥10 points above the second candidate: enter the business CLASS;
- top score 70 or 75: show candidates only, normally do not execute business SQL;
- no exact hit and candidates are not unique: ask for confirmation;
- no candidate: report that the term is not currently recorded;
- generic plant terms with multiple candidates must not be hard-selected by `LIMIT 1`;
- `anti-inflammatory` or similar terms that do not hit level-1/2/3/4 trait dictionaries must not trigger CLASS_18.

## CLASS_17 | Known functional component → homology development
### Trigger
One functional component is recognized; intent includes: homology development / functional homology / template development / new candidates / alternative development / virtual screening.

### Primary tables
`mergetable`, `dict_synonyms`

### Screening logic
CLASS_17 is evidence-based functional homology development through shared target evidence, not chemical-structure similarity screening.

Fixed execution logic:
1. Standardize the template functional component to `fc_id`.
2. Extract all targets of the template functional component in default species `Bos_taurus`.
3. Mark target evidence levels:
   - `fccore = core` → core target;
   - `fcRICH = rich` or `fcRTAR = rich` → enriched/target-supported target;
   - other targets → ordinary shared target.
4. Use all seed targets to recall candidate functional components or natural plants.
5. Sort primarily by shared core-target count, shared enriched-target count, and total shared-target count.

Hard rules:
- Do not hard-filter recall only by `fccore / fcRICH / fcRTAR`; use them only for ranking weight.
- Do not use `1-fc / 2-fc` as CLASS_17 seed evidence.
- `support_record_count` is auxiliary only, not the main ranking basis.
- Candidate SQL defaults to `LIMIT 200`; report body displays Top 20; chart displays Top 10.
- Summaries, ranking, and deduplication must be done by SQL and REPORT, not Python.

### SQL_1 candidate functional components: all-target recall + core/enrichment weighted ranking
```sql
SELECT
       'fc_homology_candidate_all_gene_weighted' AS result_section,
       m.fc_id AS candidate_id,
       MIN(m.fc_name) AS candidate_name,
       COUNT(DISTINCT m.nptarget_symbol) AS total_overlap_gene_count,
       COUNT(DISTINCT CASE WHEN seed_gene.seed_core_flag = 1 THEN m.nptarget_symbol END) AS core_overlap_gene_count,
       COUNT(DISTINCT CASE WHEN seed_gene.seed_rich_flag = 1 THEN m.nptarget_symbol END) AS rich_overlap_gene_count,
       GROUP_CONCAT(DISTINCT m.nptarget_symbol ORDER BY m.nptarget_symbol SEPARATOR ', ') AS total_overlap_genes,
       GROUP_CONCAT(DISTINCT CASE WHEN seed_gene.seed_core_flag = 1 THEN m.nptarget_symbol END ORDER BY m.nptarget_symbol SEPARATOR ', ') AS core_overlap_genes,
       GROUP_CONCAT(DISTINCT CASE WHEN seed_gene.seed_rich_flag = 1 THEN m.nptarget_symbol END ORDER BY m.nptarget_symbol SEPARATOR ', ') AS rich_overlap_genes,
       COUNT(DISTINCT m.fnp_id) AS related_np_count,
       COUNT(*) AS support_record_count
FROM (
    SELECT
           seed.nptarget_symbol,
           MAX(CASE WHEN LOWER(TRIM(COALESCE(seed.fccore, ''))) = 'core' THEN 1 ELSE 0 END) AS seed_core_flag,
           MAX(CASE WHEN LOWER(TRIM(COALESCE(seed.fcRICH, ''))) = 'rich'
                     OR LOWER(TRIM(COALESCE(seed.fcRTAR, ''))) = 'rich'
                    THEN 1 ELSE 0 END) AS seed_rich_flag
    FROM mergetable seed
    JOIN (
        SELECT DISTINCT d.standard_value
        FROM dict_synonyms d
        WHERE (d.alias = 'USER_KEYWORD' OR d.standard_value = 'USER_KEYWORD')
          AND d.type = '功能组分'
    ) seed_fc
      ON seed.fc_id = seed_fc.standard_value
    WHERE seed.Species = 'Bos_taurus'
      AND seed.nptarget_symbol IS NOT NULL
      AND seed.nptarget_symbol <> ''
    GROUP BY seed.nptarget_symbol
) seed_gene
JOIN mergetable m
  ON m.Species = 'Bos_taurus'
 AND m.nptarget_symbol = seed_gene.nptarget_symbol
WHERE m.fc_id IS NOT NULL
  AND m.fc_id <> ''
  AND m.fc_id NOT IN (
      SELECT DISTINCT d.standard_value
      FROM dict_synonyms d
      WHERE (d.alias = 'USER_KEYWORD' OR d.standard_value = 'USER_KEYWORD')
        AND d.type = '功能组分'
  )
GROUP BY m.fc_id
ORDER BY core_overlap_gene_count DESC,
         rich_overlap_gene_count DESC,
         total_overlap_gene_count DESC,
         related_np_count DESC,
         candidate_name
LIMIT 200;
```

```sql
    FROM dict_synonyms d JOIN mergetable m ON m.Trait_namec2 = d.standard_value
    WHERE d.type='二级表观' AND (d.alias='USER_KEYWORD' OR d.standard_value='USER_KEYWORD') AND m.Species='Bos_taurus'
      AND m.fnp_id IS NOT NULL AND m.fnp_id<>'' AND m.np_name IS NOT NULL AND m.np_name<>''
    UNION ALL
    SELECT d.type, d.standard_value, 100, m.fnp_id, m.np_name, m.nptarget_symbol, m.annotate_id,
           CASE WHEN LOWER(TRIM(COALESCE(m.`1-np`, '')))='rich' THEN 1 ELSE 0 END,
           CASE WHEN LOWER(TRIM(COALESCE(m.`2-np`, '')))='rich' THEN 1 ELSE 0 END
    FROM dict_synonyms d JOIN mergetable m ON m.Trait_namee3 = d.standard_value
    WHERE d.type='三级表观' AND (d.alias='USER_KEYWORD' OR d.standard_value='USER_KEYWORD') AND m.Species='Bos_taurus'
      AND m.fnp_id IS NOT NULL AND m.fnp_id<>'' AND m.np_name IS NOT NULL AND m.np_name<>''
    UNION ALL
    SELECT d.type, d.standard_value, 100, m.fnp_id, m.np_name, m.nptarget_symbol, m.annotate_id,
           CASE WHEN LOWER(TRIM(COALESCE(m.`1-np`, '')))='rich' THEN 1 ELSE 0 END,
           CASE WHEN LOWER(TRIM(COALESCE(m.`2-np`, '')))='rich' THEN 1 ELSE 0 END
    FROM dict_synonyms d JOIN mergetable m ON m.Trait_ID = d.standard_value
    WHERE d.type='四级表观' AND (d.alias='USER_KEYWORD' OR d.standard_value='USER_KEYWORD') AND m.Species='Bos_taurus'
      AND m.fnp_id IS NOT NULL AND m.fnp_id<>'' AND m.np_name IS NOT NULL AND m.np_name<>''
) x
GROUP BY x.fnp_id, x.np_name
ORDER BY rich_evidence_count DESC, support_gene_count DESC, support_annotate_count DESC, support_record_count DESC, candidate_name
LIMIT 200;
```

### Output template
Output two English tables: candidate functional components and candidate natural plants. Mark `rich_evidence_count > 0` as `enrichment-supported / significant association`; otherwise mark `potentially related`. Body displays Top 20. Add a Top 10 candidate bar chart. Deduplicate by `candidate_id`.
